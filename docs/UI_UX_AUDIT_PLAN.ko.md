# Clearcut 전체 UI/UX 감사 및 개선 계획

## 구현 상태 · 2026-08-23

- 1단계 완료: `결과`를 `미리보기`로 명확히 하고 저장 전/저장 완료 badge, `저장 완료 N / N`, `출력 설정 초기화` 범위 안내와 일반 화면의 개발 용어 교체
- 2단계 완료: Inspector를 `모든 파일 · 출력과 저장`과 `현재 파일 · 객체 선택과 가장자리 감지`로 구분하고 프리셋의 기호 버튼을 명시적 저장·삭제 버튼으로 교체
- 3단계 완료: 작은 설명 text와 대비, 클릭 영역, 색상에만 의존하던 파일 상태, checkbox focus 위치, tab 방향키, aria-live와 좌우 panel 접기를 보강
- 반응형 확인 완료: 1320×820과 최소 900×640 browser rendering에서 toolbar 충돌과 horizontal overflow가 없음을 확인
- 4단계의 실제 사용자 과제 관찰은 배포 후보를 이용한 별도 사용성 시험으로 유지한다.

## 1. 목표

처음 사용하는 사람이 별도 설명 없이 다음 흐름을 완수할 수 있어야 한다.

1. 파일 또는 폴더 추가
2. 자동 제거 결과 확인
3. 필요할 때 객체·가장자리 보정
4. 출력 형식·크기·저장 위치 확인
5. 저장 실행과 완료 파일 확인

전문 용어를 이해해야만 조작할 수 있는 화면, 100% 배율에서도 읽기 어려운 보조 문구, 현재 상태와 버튼 결과가 불명확한 표현을 우선 제거한다.

## 2. 현재 감사에서 확인한 개선점

### P0 · 오해 또는 작업 실패 가능성

- `결과` 탭은 저장된 최종 파일뿐 아니라 아직 저장하지 않은 편집 미리보기도 보여준다. `편집 미리보기`와 `저장 결과`의 의미를 구분해야 한다.
- 하단의 `결과 0 / N개`는 아직 실행하지 않은 상태에서 실패처럼 보일 수 있다. `저장 완료 0 / N`과 `예상 용량`을 분리한다.
- 우측 상단 `초기화`는 출력 설정 전체만 초기화하지만 파일별 가장자리나 앱 환경설정까지 초기화한다고 오해할 수 있다. `출력 설정 초기화`로 범위를 명시하고 확인 또는 Undo 안내를 제공한다.
- 비활성화된 `결과·마스크·비교` 탭은 사용할 수 없는 이유가 보이지 않는다. hover/focus 도움말과 바로 실행할 수 있는 다음 행동을 표시한다.
- `recipe`, `batch`, `fallback`, `worker protocol` 같은 개발 용어가 일반 설정 안내에 섞여 있다. 일반 화면에서는 각각 `설정 조합`, `일괄 처리`, `자동 전환`, `처리 엔진 버전`으로 바꾼다. 원문은 진단 화면에만 남긴다.

### P1 · 가독성과 조작성

- 8~9.5px 보조 문구가 미리보기 편집기, 프리셋, 고급 설정, 환경설정에 많이 사용된다. Windows 100~150% 배율에서 본문 12px, 보조 문구 11px, 핵심 label 12px를 최소 기준으로 재정의한다.
- `--ink-faint` 색은 흰 배경의 작은 글자에서 대비가 낮다. 설명용 text token을 더 진하게 만들고, 장식·비활성 상태에만 현재 faint 색을 사용한다.
- 프리셋의 `＋`, `−`는 저장과 삭제라는 의미가 즉시 드러나지 않는다. `현재 설정 저장` 버튼과 선택 프리셋의 더보기 메뉴 또는 명시적인 `삭제`로 변경한다.
- 회전·삭제·환경설정처럼 icon만 있는 버튼은 마우스 tooltip에 의존한다. 자주 쓰는 작업에는 짧은 label을 제공하고 좁은 창에서만 icon 형태로 축약한다.
- 작은 token 버튼과 고급 설정 초기화 버튼의 클릭 영역이 작다. 주요 interactive target은 높이 32px 이상, 반복 사용 도구는 36px 이상으로 통일한다.
- 파일 상태는 작은 색 점에 의존한다. 색뿐 아니라 `대기·처리 중·완료·오류` text 또는 접근 가능한 상태 badge를 제공한다.

### P1 · 정보 구조

- 우측 Inspector가 프리셋, 처리 방식, 형식, 크기, 위치, 파일명, 마스크, 가장자리를 한 열에 모두 노출해 스크롤이 길다. `출력`과 `편집` 두 영역으로 묶고, 현재 작업에 필요한 영역을 먼저 연다.
- `전체 설정`, `파일별 · 미리보기`, `동적 규칙` badge는 범주가 서로 다르지만 같은 시각 표현을 사용한다. 범위 badge(`모든 파일`, `현재 파일`)와 상태 badge(`실시간`, `저장됨`)를 분리한다.
- 자동 제거 AI 상태 pill은 상태 표시처럼 보이지만 다음 행동과 연결되지 않는다. 미설치·오류 상태에서는 환경설정의 모델 화면으로 이동할 수 있게 하고, 정상 상태에서는 단순 상태로 유지한다.
- 작업 목록 제거는 원본 삭제로 오해할 수 있다. 메뉴 문구를 `목록에서 제거 · 원본 유지`로 명확하게 표시한다.

### P2 · 좁은 창과 접근성

- 900×640, 125%·150% 배율에서 도구막대와 브러시 편집 패널의 겹침·잘림을 점검한다. 좁은 폭에서는 파일 목록 또는 Inspector를 접을 수 있는 방식이 필요하다.
- 탭과 비교 slider의 키보드 이동, focus 순서, Esc 취소, Enter 적용을 하나의 규칙으로 통일한다.
- 미리보기 갱신·모델 설치·일괄 처리 상태는 화면 표시뿐 아니라 `aria-live`로 전달한다.
- 오류 toast에는 `닫기` 외에 가능한 경우 `다시 시도`, `설정 열기`, `파일 위치 열기` 같은 복구 행동을 제공한다.

## 3. 실행 순서

### 1단계 · 문구와 시각 토큰 정리

- 사용자 화면의 전문 용어와 모호한 초기화·결과 표현 교체
- type scale, text contrast, 최소 클릭 영역을 공통 token으로 정의
- 프리셋 버튼, 파일 상태, 비활성 탭 도움말 개선

이 단계는 처리 로직을 건드리지 않아 회귀 위험이 낮고 체감 개선이 가장 크다.

### 2단계 · 미리보기와 Inspector 정보 구조 개편

- `원본 / 편집 미리보기 / 마스크 / 비교`의 상태 정의
- 저장 전 미리보기와 실제 저장 결과의 badge·문구 분리
- Inspector를 `편집`과 `출력` 영역으로 재구성하고 파일별·전체 범위를 명시
- 프리셋 저장·갱신·이름 변경·삭제 흐름을 명시적 버튼과 menu로 교체

### 3단계 · 반응형·접근성 보강

- 좌측 목록과 우측 Inspector 접기
- 900×640부터 150% 배율까지 horizontal overflow와 패널 겹침 제거
- keyboard-only 흐름, focus 표시, aria-live, 색상 외 상태 표현 검증

### 4단계 · 사용성 검증

다음 과제를 사전 설명 없이 수행하도록 관찰한다.

1. 이미지 20개를 추가하고 1개만 가장자리 보정
2. 편집 미리보기와 저장 결과를 구분해 확인
3. WebP 80%, 긴 변 1600px, 지정 폴더 설정을 프리셋으로 저장 후 다시 불러오기
4. 목록에서 파일 하나를 제거하되 원본이 유지됨을 확인
5. 실패한 항목의 원인을 확인하고 재시도

## 4. 완료 기준

- 900×640, 1320×820에서 100%·125%·150% 배율로 horizontal scroll이 발생하지 않는다.
- 일반 화면의 의미 있는 text는 원칙적으로 11px 이상이며 본문은 12px 이상이다.
- 핵심 text와 배경은 WCAG AA 대비를 충족하고 상태를 색만으로 전달하지 않는다.
- 사용자가 `현재 파일` 설정과 `모든 파일` 출력 설정을 잘못 구분하지 않는다.
- 마우스 없이 파일 선택, 탭 전환, 브러시 적용·취소, 출력 실행이 가능하다.
- 첫 사용자 테스트에서 위 5개 과제를 도움 없이 완료하고, 저장 전 미리보기와 실제 결과를 혼동하지 않는다.
